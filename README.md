## Структура pipeline

Файл расположен в `.github/workflows/ci.yml` и запускается при каждом `push` в ветку текущей практики `pz8`.

Pipeline состоит из двух этапов `jobs`:
- go test + go build
- сборка и push образов в ghcr.io

### Job: test — тесты и сборка

| Шаг | Что делает |
|-----|------------|
| `actions/checkout@v4` | Клонирует репозиторий |
| `actions/setup-go@v5` | Устанавливает Go 1.25, кеширует модули |
| `go mod download` | Скачивает зависимости |
| `go test ./...` | Запускает все тесты проекта |
| `go build auth` | Проверяет, что auth компилируется |
| `go build tasks` | Проверяет, что tasks компилируется |

### Job: docker — сборка и публикация образов

Запускается только если `test` прошёл.

| Шаг | Что делает |
|-----|------------|
| `Set image tag` | Берёт первые 7 символов hash коммита (`abc1234`) |
| `docker/setup-buildx-action` | Настраивает BuildKit для многоплатформенной сборки |
| `docker/login-action` | Логин в `ghcr.io` через автоматический `GITHUB_TOKEN` |
| `Build & push auth` | Собирает и публикует образ auth с двумя тегами |
| `Build & push tasks` | Собирает и публикует образ tasks с двумя тегами |

## Версионирование образов

Каждый образ публикуется с двумя тегами:

| Тег | Пример | Назначение |
|-----|--------|------------|
| Короткий hash | `abc1234` | Точная привязка к коммиту |
| `latest` | `latest` | Всегда указывает на последнюю сборку из main |

Образы публикуются в **GitHub Container Registry**:
```
ghcr.io/<owner>/techip-auth:abc1234
ghcr.io/<owner>/techip-tasks:abc1234
```

## Секреты

Секреты хранятся в **Settings → Secrets and variables → Actions** репозитория.

| Секрет | Где используется | Описание |
|--------|-----------------|----------|
| `GITHUB_TOKEN` | docker job | Создаётся автоматически, вручную добавлять не нужно |

**Запрещено:** коммитить токены и ключи в репозиторий, писать их в `.yml` файлы.

## Настройка и запуск

### Создать environment для деплоя

```
GitHub → Settings → Environments → New environment → "production"
```

Включить **Required reviewers** — тогда деплой потребует ручного подтверждения.

### Запустить pipeline

Сделать `git push` в ветку `pz8`

После push перейти в **Actions** на GitHub и убедиться, что pipeline зелёный.
